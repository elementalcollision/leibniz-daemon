# ADR 0093 — A lane that cannot run must say so

- Status: **accepted — landed, measured against two months of Actions history**
- Date: 2026-09-08
- Depends on: ADR 0049 (public-repo self-hosted safety), ADR 0092 (the sibling: a beat that hangs
  writes nothing; this is the same shape one layer out)

## Context

`kernel-nightly.yml` runs the Docker-gated render→kernel tests the main `ci` lane cannot: GitHub
hosted runners have no Lean image, so the lane targets a self-hosted runner labelled `lean`. Its
own header states the design assumption:

> *If no such runner is registered, the scheduled job simply does not run — it never reports a
> false green.*

That is true. It was also not enough. Measured 2026-09-08:

```
kernel-nightly runs since 2026-07-11 : 60
  cancelled                          : 59     (GitHub expires an unclaimed job after 24h)
  queued (3h and counting)           :  1
  ever succeeded                     :  0
self-hosted runners registered       :  0
```

A lane whose commit message calls it **"no-silent-skip"** had been silently skipping every night
for two months. Nothing was wrong with the reasoning — "never a false green" held throughout. The
gap is that *an expired queue and a night that has not happened yet look identical*, so sixty
consecutive non-runs were indistinguishable from a healthy schedule nobody had checked.

This is ADR 0092's failure one layer out. There, a hung beat wrote no journal entry, so silence
meant both "fine" and "broken". Here, an unclaimed job produces `cancelled`, which reads as
routine. Both are systems whose failure mode is *absence*, and absence is what nobody notices.

## Decision 1 — a GitHub-hosted witness

A `runner-guard` job on `ubuntu-latest` polls this run's job list and fails after 10 minutes if
nothing has claimed the `kernel` job. An online runner claims a job in seconds, so the timeout only
fires when there is genuinely no runner.

It is deliberately **not** a gate: `kernel` does not `needs:` it, so the guard cannot block the
work it observes. And it asserts only that *something claimed the job* — it makes no claim about
kernel results, so it cannot manufacture the false green the original design was protecting
against. Sixty invisible expirations become one visible failure.

Permissions stay least-privilege: the workflow is `contents: read`; the guard adds `actions: read`
to see its own run, and writes nothing.

## Decision 2 — make ADR 0049's convention mechanical

This repository is **public**, and a self-hosted runner on a public repo is the configuration
GitHub explicitly warns against: a fork's pull request would execute arbitrary code on the
operator's machine. Today that exposure is closed, because the lane uses only `schedule` and
`workflow_dispatch` — and that fact lived in a *comment*.

`tests/test_selfhosted_exposure_r0093.py` now fails the BLOCKING invariants job if any workflow
pairs a self-hosted job with a fork-reachable trigger (`pull_request`, `pull_request_target`,
`issue_comment`, …). Stdlib-only, so it runs on the core install. It includes a test that the check
itself catches the dangerous shape — a guard that cannot fail is not a guard — and mutation
confirms it: adding `pull_request:` to the kernel lane turns it red.

A convention is one edit away from being false. This one is now enforced.

## Decision 3 — a runbook that states the real trade

`docs/runbooks/kernel-runner.md` covers registration, and leads with the security posture rather
than burying it: public repo, `--ephemeral` strongly recommended, non-root user, and the
registration token generated by the operator and never pasted anywhere.

It also names the option the repository had been taking by accident: **if you do not want a
self-hosted runner, delete the lane** rather than leave it queueing forever. What it must not do is
disable the guard, which would restore exactly the silence this ADR removes.

## Consequences

The lane now reports one of three things instead of nothing: it ran, it failed, or nothing claimed
it. Until a runner is registered the nightly will fail — noisy, but honest noise, and strictly
better than sixty cancellations that read as routine.

**No trust surface.** This is CI plumbing; it promulgates nothing, publishes nothing, and the
guard's claim is deliberately weaker than the lane's.

**What this does not do:** it does not register a runner — that is an operator action on their own
hardware, and the runbook stops at the point where a credential is required. It does not check that
a registered runner is `--ephemeral` or non-root, because nothing in the repository can see that. And
it does not address the third silent-scheduling failure found the same day: `launchd` firing a beat
that hangs is ADR 0092's territory, but nothing yet notices if `launchd` stops firing at all.
